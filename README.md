# lab01_ab-320_sychuk

Лабораторная работа №1: аудит и подготовка датасета событий аутентификации к классификации угроз.

**Вариант 3 (№21 в списке).** Фокусные поля: `timestamp`, `hour`, `is_weekend`, `device_type`, `os_family`, `browser_family`, `known_device`. Основная проверка - временное разделение по `timestamp`.

## Задача

Определить, является ли конкретная попытка аутентификации подозрительной, используя контекст устройства и времени события. Единица наблюдения - одна попытка входа (одна строка), решение принимается в момент попытки. Целевая переменная `is_suspicious`: `0` - нормальное событие, `1` - подозрительное. Результат предназначен для аналитика SOC: приоритизация проверок, повышение уровня логирования, запрос дополнительного фактора аутентификации, инициирование ручной верификации. Автоматическое блокирование учетной записи по одной метке не предполагается.

## Результаты

**Датасет:** 1430 строк, 23 столбца → 1298 строк, 23 столбца. Удалено 114 строк по предметным ограничениям и еще 18 полных дубликатов. Явных `NaN` 76 → 0, условных пропусков (`unknown`, `-`, `not_recorded`) 28 → 0. Доля класса 1: 9.02 % → 8.47 % (1188 / 110, соотношение ≈ 10.8 : 1).

**Очистка** (по шагам, с учетом каскадности - часть строк снимается несколькими правилами). Удалены: невалидный `event_id` - 12; непарсящийся `timestamp` - 3; `failed_attempts_24h < 0` - 3; `distance_from_usual_km < 0` - 4; `account_age_days < 0` - 3; `password_age_days > account_age_days` - 89 из 93 (4 уже удалены предыдущими правилами). Заполнены вместо удаления: `distance_from_usual_km = NaN` - 32 медианой; `password_age_days = unknown` - 9 медианой; `browser_family` NaN/`-` - 37 заменой на категорию `Other`; `department` NaN/`unknown` - 21 заменой на категорию `Other`. Единичное расхождение `hour` с `timestamp.dt.hour` исправлено восстановлением из `timestamp`. Типы всех 23 столбцов приведены к словарю (`datetime`, `int32`, `int8`, `float32`, `category`, `string`).

**Дубликаты:** 18 полных пар (36 строк) - технические копии, удалены с сохранением первых вхождений. После дедупликации 1298 уникальных `event_id` на 1298 строк. Множественные события одного пользователя (113 пользователей, в среднем 11.49 события) дубликатами не считаются - это самостоятельные попытки входа.

**Выбросы** оставлены в наборе: расстояние и скорость входов - информативные сигналы компрометации. По правилу 1.5 IQR затронута 91 уникальная строка (`distance_from_usual_km` - 72, `login_velocity_1h` - 48, `failed_attempts_24h` - 28). Отдельно зафиксированы технические заглушки: `distance_from_usual_km = 20000` (5 строк) и `failed_attempts_24h = 999` (2 строки).

**Утечки.** `analyst_verdict` совпадает с `is_suspicious` в 100 % случаев, `analyst_risk_score` - средние 36.05 (класс 0) против 88.23 (класс 1), корреляция 0.613. Оба поля появляются после принятия решения и исключены из X. Также исключены `event_id`, `timestamp` (ключ разделения), `user_id`, `source_ip`. В X осталось 16 признаков, все доступны в момент решения.

Сильнейший доступный сигнал - `new_country` (корреляция 0.622), далее `login_velocity_1h` (0.547), `distance_from_usual_km` (0.434), `known_device` (0.319). Это задает ожидаемый профиль модели: контекст события, а не "узнавание" пользователя.

**Разделение.** Основная схема - временная по `timestamp` (80/20): train 1038, test 260, `max(train.timestamp) <= min(test.timestamp)`. Доля класса 1: 6.55 % в train против 16.15 % в test - временной дрейф, а не ошибка разделения. 101 пользователь из 101 встречающегося в test присутствует и в train. Для сравнения реализованы также стратифицированная случайная (1038/260, 8.48 % / 8.46 %, пересечение по `user_id` = 99) и групповая по `user_id` (1035/263, 7.63 % / 11.79 %, пересечение = 0).

**Pipeline:** `ColumnTransformer` - для 10 числовых признаков `SimpleImputer(median)` + `RobustScaler`, для 6 категориальных `SimpleImputer(most_frequent)` + `OneHotEncoder(handle_unknown='ignore')`. `fit_transform` только на `X_train`, `transform` только на `X_test`; параметры выучены по train и не пересчитываются. Итог: 1038×45 и 260×45, ни одного `NaN` или `inf`.

## Риски и ограничения

1. **Технические заглушки** (`20000` в расстоянии, `999` в счетчике попыток) искажают распределение - среднее `distance_from_usual_km` 376.5 км при медиане 31.2 км. Мера: реестр заглушек и мониторинг их вклада через feature importance.
2. **Временной дрейф** - доля класса 1 растет с 6.55 % до 16.15 %, 101 пользователь переходит из train в test. Мера: сравнение метрик с групповой схемой (пересечение = 0) для проверки устойчивости к новым пользователям.
3. **Синтетическая природа данных** - правило разметки неизвестно, метка почти выводится из `analyst_verdict`. Мера: ограничение выводов рамками учебной задачи, валидация на реальных данных и ручная верификация аналитиком перед внедрением.

Результаты получены на синтетическом наборе и не переносятся напрямую на реальную систему без дополнительной валидации.
