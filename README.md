# lab01_ab-320_sychuk

Лабораторная работа №1: аудит и подготовка датасета событий аутентификации к классификации угроз.

**Вариант 3 (№21 в списке).** Фокусные поля: `timestamp`, `hour`, `is_weekend`, `device_type`, `os_family`, `browser_family`, `known_device`. Основная проверка - временное разделение по `timestamp`.

## Задача

Определить, является ли конкретная попытка аутентификации подозрительной, используя контекст устройства и времени события. Единица наблюдения - одна попытка входа (одна строка), решение принимается в момент попытки. Целевая переменная `is_suspicious`: `0` - нормальное событие, `1` - подозрительное. Результат предназначен для аналитика SOC: приоритизация проверок, повышение уровня логирования, запрос дополнительного фактора аутентификации, инициирование ручной верификации. Автоматическое блокирование учетной записи по одной метке не предполагается.

## Результаты

**Дасет:** 1430 строк, 23 столбца → 1203 строки, 23 столбца. Удалено 209 строк по предметным ограничениям и еще 18 полных дубликатов. Явных `NaN` 76 → 0, условных пропусков (`unknown`, `-`, `not_recorded`) 28 → 0. Доля класса 1: 9.02 % → 8.56 % (1100 / 103, соотношение ≈ 10.7 : 1).

**Очистка** (по шагам, с учетом каскадности - часть строк снимается несколькими правилами): невалидный `event_id` - 12; непарсящийся `timestamp` - 3; `failed_attempts_24h < 0` - 3; `distance_from_usual_km < 0` - 4; `distance_from_usual_km = NaN` - 32; `account_age_days < 0` - 3; `password_age_days = unknown` - 9; `password_age_days > account_age_days` - 85 из 93; `browser_family` NaN/`-` - 37 из 40; `department` NaN/`unknown` - 21 из 22. Единичное расхождение `hour` с `timestamp.dt.hour` исправлено восстановлением из `timestamp`. Типы всех 23 столбцов приведены к словарю (`datetime`, `int32`, `int8`, `float32`, `category`, `string`).

**Дубликаты:** 18 полных пар (36 строк) - технические копии, удалены с сохранением первых вхождений. После дедупликации 1203 уникальных `event_id` на 1203 строки. Множественные события одного пользователя (113 пользователей, в среднем 10.65 события) дубликатами не считаются - это самостоятельные попытки входа.

**Выбросы** оставлены в наборе: расстояние и скорость входов - информативные сигналы компрометации. По правилу 1.5 IQR затронуто 84 уникальные строки (`distance_from_usual_km` - 69, `login_velocity_1h` - 45, `failed_attempts_24h` - 26). Отдельно зафиксированы технические заглушки: `distance_from_usual_km = 20000` (5 строк) и `failed_attempts_24h = 999` (2 строки).

**Утечки.** `analyst_verdict` совпадает с `is_suspicious` в 100 % случаев, `analyst_risk_score` - средние 35.89 (класс 0) против 88.37 (класс 1), корреляция 0.618. Оба поля появляются после принятия решения и исключены из X. Также исключены `event_id`, `timestamp` (ключ разделения), `user_id`, `source_ip`. В X осталось 16 признаков, все доступны в момент решения.

Сильнейший доступный сигнал - `new_country` (корреляция 0.636), далее `login_velocity_1h` (0.550), `distance_from_usual_km` (0.442), `known_device` (0.328). Это задает ожидаемый профиль модели: контекст события, а не "узнавание" пользователя.

**Разделение.** Основная схема - временная по `timestamp` (80/20): train 962, test 241, `max(train.timestamp) <= min(test.timestamp)`. Доля класса 1: 6.76 % в train против 15.77 % в test - временной дрейф, а не ошибка разделения. 97 пользователей из 97 встречающихся в test присутствуют и в train. Для сравнения реализованы также стратифицированная случайная (962/241, 8.52 % / 8.71 %, пересечение по `user_id` = 98) и групповая по `user_id` (963/240, 8.52 % / 8.75 %, пересечение = 0).

**Pipeline:** `ColumnTransformer` - для 10 числовых признаков `SimpleImputer(median)` + `RobustScaler`, для 6 категориальных `SimpleImputer(most_frequent)` + `OneHotEncoder(handle_unknown='ignore')`. `fit_transform` только на `X_train`, `transform` только на `X_test`; параметры выучены по train и не пересчитываются. Итог: 962×43 и 241×43, ни одного `NaN` или `inf`.

## Риски и ограничения

1. **Технические заглушки** (`20000` в расстоянии, `999` в счетчике попыток) искажают распределение - среднее `distance_from_usual_km` 376.5 км при медиане 31.2 км. Мера: реестр заглушек и мониторинг их вклада через feature importance.
2. **Временной дрейф** - доля класса 1 растет с 6.76 % до 15.77 %, 97 пользователей переходят из train в test. Мера: сравнение метрик с групповой схемой (пересечение = 0) для проверки устойчивости к новым пользователям.
3. **Синтетическая природа данных** - правило разметки неизвестно, метка почти выводится из `analyst_verdict`. Мера: ограничение выводов рамками учебной задачи, валидация на реальных данных и ручная верификация аналитиком перед внедрением.

Результаты получены на синтетическом наборе и не переносятся напрямую на реальную систему без дополнительной валидации.
